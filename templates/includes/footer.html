{# 1. Autentikasi & Otorisasi #}
1. Autentikasi & Otorisasi
Aktif
  • Login wajib untuk semua halaman — semua URL dilindungi oleh SessionSecurityMiddleware dan LoginRequiredMixin. Pengguna yang belum masuk diarahkan otomatis ke halaman login.
  • Kontrol akses berbasis peran — setiap pengguna hanya dapat mengakses menu dan data sesuai hak akses yang diberikan administrator.
  • Password terenkripsi menggunakan algoritma PBKDF2 + SHA-256 dengan salt acak (Django default). Password divalidasi: minimal panjang, tidak umum, tidak mirip nama pengguna.
  • Halaman login dilindungi dari serangan brute-force melalui validasi form Django.
{# 2. Manajemen Sesi #}
2. Manajemen Sesi
Aktif
  • Batas waktu idle 30 menit — sesi otomatis berakhir dan pengguna diarahkan ke halaman login jika tidak ada aktivitas selama 30 menit (IDLE_TIMEOUT = 1800 detik).
  • Sesi tutup browser — sesi berakhir otomatis saat browser ditutup (SESSION_EXPIRE_AT_BROWSER_CLOSE = True).
  • Cookie HttpOnly — cookie sesi tidak dapat diakses oleh JavaScript (SESSION_COOKIE_HTTPONLY = True), mencegah pencurian cookie melalui XSS.
  • SameSite Lax — cookie dilindungi dari serangan Cross-Site Request Forgery berbasis navigasi (SESSION_COOKIE_SAMESITE = 'Lax').
  • No-Cache pada halaman terproteksi — semua respons halaman private menyertakan header Cache-Control: no-store agar tidak tersimpan di cache browser.
{# 3. Perlindungan CSRF #}
3. Perlindungan CSRF
Aktif
  • Token CSRF pada setiap formulir — semua permintaan POST diverifikasi dengan token acak Django (CsrfViewMiddleware). Permintaan tanpa token yang valid ditolak.
  • CSRF Trusted Origins — hanya asal (origin) yang terdaftar dapat mengirimkan permintaan lintas domain (CSRF_TRUSTED_ORIGINS).
  • Halaman gagal CSRF kustom — pengguna mendapat pesan yang jelas bila token CSRF tidak valid, bukan halaman error generik.
{# 4. Header Keamanan HTTP #}
4. Header Keamanan HTTP
Aktif
Header Nilai / Efek
Content-Security-Policy Memblokir skrip, style, dan sumber daya dari domain asing yang tidak diizinkan. Mencegah serangan XSS dan injeksi konten.
X-Content-Type-Options nosniff — Browser tidak diizinkan menebak tipe konten (mencegah MIME-sniffing attack).
X-Frame-Options DENY — Halaman tidak dapat dimuat dalam iframe dari domain lain (mencegah clickjacking).
Referrer-Policy same-origin — URL referrer hanya dikirim ke domain yang sama, tidak bocor ke situs luar.
Cross-Origin-Opener-Policy same-origin — Mencegah akses lintas-origin ke objek window (isolasi konteks browser).
Cross-Origin-Resource-Policy same-origin — Mencegah sumber daya dimuat dari domain lain tanpa izin.
Permissions-Policy Kamera, mikrofon, payment, dan USB dinonaktifkan. Geolokasi hanya untuk domain sendiri.
X-Permitted-Cross-Domain-Policies none — Adobe Flash/PDF tidak diizinkan mengakses lintas domain.
{# 5. Keamanan Database & Data #}
5. Keamanan Database & Data
Aktif
  • ORM Django (SQL Injection Protection) — semua query database menggunakan Django ORM dengan parameterisasi otomatis, sehingga data pengguna tidak pernah langsung dimasukkan ke dalam query SQL mentah.
  • Kredensial dari Docker Secrets — kunci rahasia (SECRET_KEY), nama database, pengguna, dan password dibaca dari /run/secrets/ (Docker Swarm Secrets), bukan dari variabel lingkungan terbuka, sehingga tidak terekspos di log atau proses list.
  • Database PostgreSQL terpisah dari aplikasi web dalam jaringan Docker internal, tidak dapat diakses langsung dari luar container.
  • Debug mode nonaktif (DEBUG = False) di lingkungan produksi — pesan error detail tidak pernah ditampilkan kepada pengguna akhir.
{# 6. HTTPS & Transport #}
6. Enkripsi Transport (HTTPS)
Siap Aktifkan
  • Dukungan HTTPS penuh tersedia — sistem sudah dikonfigurasi untuk HTTPS dengan pengaturan USE_HTTPS = True. Saat diaktifkan, seluruh lalu lintas data dienkripsi dengan TLS/SSL.
  • HSTS (HTTP Strict Transport Security) — saat HTTPS aktif, browser dipaksa selalu menggunakan HTTPS untuk domain ini selama 1 tahun (SECURE_HSTS_SECONDS = 31536000) termasuk subdomain dan preload list.
  • Secure Cookie — saat HTTPS aktif, cookie sesi dan CSRF hanya dikirim melalui koneksi terenkripsi (SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE).
  • Status saat ini: Sistem berjalan di jaringan intranet lokal menggunakan HTTP. Untuk internet/publik, aktifkan HTTPS dengan sertifikat TLS dari Let's Encrypt melalui Nginx reverse proxy.
